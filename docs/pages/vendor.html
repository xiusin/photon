依赖与 Vendor

Photon 唯一的第三方依赖是 Redis 客户端，它被 vendor 进仓库由本仓库维护 —— 一份源码、一处修改、一套测试。

📦 零外部依赖vendor/modules/xiusin/vredisfunctional coverage
📦
依赖现状
框架本体不依赖任何外部模块
依赖位置角色维护方式
xiusin.vredisvendor/modules/xiusin/vredis/Redis 客户端（缓存 / 队列 / 分布式锁后端）本仓库维护

v.mod 里的 dependencies 现在是空的 —— 唯一曾经的外部依赖已经进仓库了。 其余 23 个模块（core / config / web / orm / cache / locking / queue …）只用 V 标准库。

为什么不再用 v install
上游 vredis 写于更早的 V 版本，在 V 0.5.2 上需要打补丁才能编译。补丁脚本意味着 CI、本地、Docker 三处各自打补丁，上游一次静默改动就能让补丁失配 —— 而失配时报的错 离真因很远。vendor 进仓库后，这些都不再存在。
🔗
本地接入
一条命令，幂等
sh
# 把 ~/.vmodules/xiusin/vredis 链接到仓库内目录 sh scripts/sync-vendor.sh # 等价于 make vendor

之后 v test cache/、v test vendor/modules/xiusin/vredis/、 v -prod example/ 都能正常工作。CI、Dockerfile、ci-test.sh 用的是同一条命令。

为什么需要这一步

V 的模块搜索只认 <project>/ 与 <project>/modules/，而且只认一层目录名。 vendor/modules/xiusin/vredis 满足了目录布局（modules/ 让 V 把它当模块根）， 但 v test vendor/modules/xiusin/vredis/ 这种单目录模式只把文件所在目录当搜索根， 找不到 x.json2。符号链接把两边的搜索根对齐。

命令结果
make test / v test cache/通过 ~/.vmodules 找到 vredis 与 x.json2
make test-vendor对真实 Redis 跑 vredis 的功能覆盖测试
make test-all先 make vendor，再跑全部 23 个模块

为 V 0.5.2 与新语义做的修改
每一处都在源码里有注释
位置改动原因
import json→ import x.json2V 0.5.2 的 JSON 模块挂在 x.json2
Reply 读取器错误回复转成 Result error见下：错误被静默丢掉
SetOpts字段加 pub:模块外根本无法构造 SetOpts{nx: true}
Pool.get()select 分支改用 ClientHandleV 0.5.2 的 select 分支变量不可变
Protocol新增 read_exact_line()TcpConn.read_line() 在 \r\n 行尾会提前返回
pubsub()返回 &Reply 而非 string数组回复被 bytestr() 读成空串
subscribe_()超时改 24h 而非 0net 把 read_timeout = 0 当「立刻超时」

「不报错但结果是错的」四连

上游把 -ERR ... 解析成 Reply.kind == .error 之后就不再处理。 所有返回值型命令都用 .ok() / .int() / .str() 判读，于是：

v
// 1. INCR 打在非数字值上 → Redis 回 -ERR，上游 .int() 把错误文本读成 0 // 2. SET k v NX 撞上已存在的键 → nil 回复，.ok() = false，看着像「业务不满足」 // 3. RENAME 目标不存在 → -ERR，.ok() = false // 4. 订阅循环 read_line() 提前返回 → 订阅成功但一条消息都收不到 // 现在所有 !T 命令包装都先过 reply_or_err()： if v := client.incr('not-a-number') { // 不会走到这里 } else { // err.msg() 以 "redis: ERR value is not an integer" 开头 }
